# Phase 7 Research Desk First-Client Playbook

Use this playbook for the first paid Research Desk reviews. The goal is to extend the automated validation report without implying that the automated run proved more than it did.

## Intake

1. Confirm the client is on a Research Desk-eligible plan or has an admin pilot override.
2. Ask the client to create the request from a specific report limitation or assumption-ledger item.
3. Confirm the generated packet includes the report snapshot, artifact manifest, evidence ledger, assumption ledger, unsupported claims, diagnostic outputs, requested questions, and client note.
4. Reject vague requests that are not tied to a report snapshot or decision.

## Scoping

Move the request through:

- received
- scoped
- quoted
- in_review
- addendum_draft
- approved
- delivered
- closed

Every request should select at least one concrete scope:

- execution audit
- data quality audit
- benchmark construction
- parameter stability review
- regime/context review
- claim validation
- investor/buyer memo review

## Reviewer Policy

An approved addendum must:

- answer the trigger limitation directly
- identify evidence that remains missing
- separate artifact limits, engine limits, and commercial scope
- avoid investment advice and performance promises
- state whether claims should be narrowed, supported with more evidence, or removed
- attach only public, report-safe language to the report snapshot

Keep internal notes separate from approved public addenda.

## Delivery

1. Approve the addendum only when the public text is report-safe.
2. Verify the addendum appears on the client report and shared report.
3. Move the request to delivered after client notification.
4. Move to closed when no follow-up evidence is pending.

## Learning Loop

Repeated limitations should be reviewed as product signals. When the same limitation appears three or more times, consider promoting it into a product workflow, diagnostic requirement, onboarding copy, or upload checklist.
